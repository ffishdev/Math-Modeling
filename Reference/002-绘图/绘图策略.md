# 华为杯数学建模论文绘图策略

## 1. 目标与总原则

本策略综合《数据建模手册》和 `Reference/005-近年优秀论文阅读.md` 中七篇论文的图表观察，用于题目分析、数据审查、建模验证、结果解释和论文排版。参考论文提供的是表达经验，不是可直接照搬的图型、配色或结论；每幅图仍须服从当年题目、原始数据、可复现计算和竞赛格式要求。

绘图首先回答“这幅图要支持哪一个判断”，再决定画什么、用什么工具。建议按“题目要求—数据与变量—方法步骤—验证证据—方案或结论”组织全篇图表。每幅图应有明确的核心信息，并能追溯到数据、代码或可编辑源文件。流程图用于解释方法，不能代替结果验证；热图、雷达图和降维图也不能自动成为有效性证据。

在图面和图注中清楚区分：原始观测、模型估计、仿真/情景结果和概念示意。仿真或示意结果不可伪装成实测结果；对无标签样本，模型置信度或嵌入图不证明预测正确；相关性和由同一指标派生的量不应被写成独立验证。

## 3. 按建模任务选择图表

| 任务/论点 | 优先考虑的图表 | 绘制与解释要求 |
|---|---|---|
| 数据清点与预处理 | 缺失率/缺失模式、分布与箱线、类别比例、时间覆盖、处理前后对照 | 同时报样本量和筛选规则；异常检测只标记待核查点，不把统计阈值直接当作删除依据。 |
| 评价与决策 | 指标方向与权重、得分/排序点图、理想距离或方案比较、权重扰动下的排序稳定性 | 明确正向/逆向指标、归一化、权重来源和候选集合；雷达图仅作概览，最好配精确数值或排序图。 |
| 预测与动态过程 | 按时间分开的训练/验证/测试曲线、观测与预测、预测区间、残差、基线比较 | 标明时间跨度、采样单位、拆分边界和区间定义；训练集拟合图不能单独作为预测能力证据。 |
| 优化与方案设计 | 可行域/可行性检查、Pareto 前沿、收敛轨迹、多次运行分布、约束违反量、候选方案空间图 | 写清目标方向、硬约束、基线和最终方案的选取原则；启发式算法的收敛图不能证明全局最优。 |
| 分类与诊断 | 混淆矩阵、适合类别分布的 ROC 或 PR 曲线、逐类指标、校准/错误案例、训练与验证曲线 | 类别顺序和验证拆分必须清楚；类别不平衡时不能只报告准确率；窗口/样本按来源分组以避免泄漏。 |
| 聚类、无监督和迁移 | 簇数依据、轮廓/稳定性、域间特征分布、降维探索图、代表样本对照 | 报告尺度处理与稳定性；t-SNE/UMAP 仅用于探索，不能替代标签验证或独立测试。 |
| 空间、图网络与三维重构 | 路网/节点边图、密度/场热图、关键路径、三维视图、正交切片/剖面 | 标明坐标系、方向、比例尺、高度、边权含义和单位；同类图共用范围与色条，三维视图提供二维补充。 |
| 随机仿真与情景分析 | 多次模拟分布、均值/分位区间、情景对照、敏感性曲线 | 标明模拟次数、随机种子或情景假设；不要只展示一条有利轨迹，也不要把模拟说成实测。 |
| 图像识别与几何提取 | 同一样本的原图—预处理—模型输出—标注/真值对照，误差或边界偏差 | 保留相同裁剪与比例；叠加颜色含义清楚，给出代表样本选择依据，并用定量指标补充视觉比较。 |

手册中的 AHP、熵权、TOPSIS、GM(1,1)、ARIMA、树模型、神经网络、启发式优化等方法与图型都只是候选。图应显示所选方法在当前数据上的适用性或验证结果，不能因手册列出某类图就机械套用。

## 4. 三种绘图方式及选用边界

| 方式 | 适合承载的内容 | 质量控制与边界 | 应保留的产物 |
|---|---|---|---|
| GPT 图像生成模型（Image） | 概念插图、机制/场景示意、视觉草案；经核验后可用于论文中的非量化示意图。 | 不用于生成真实数据曲线、统计图、数值、坐标轴或模型效果；不得让模型补造机制/因果关系。文字、箭头和结构需人工校对；标明“示意”并检查竞赛提交要求对生成式图像的规定。 | 提示词与版本/日期、参考素材权利、选用图、人工修订记录；重要文字和结构尽可能用可编辑工具重绘。 |
| Python 或 MATLAB 直接绘制 | 所有由数据计算得到的统计图、模型结果图和重复实验图；利于批量更新和复现。 | 以真实输入和明确的数据处理/统计定义生成；比较图使用一致尺度；保留随机种子、参数和拆分；代码出图后仍须人工检查图面。 | Python/MATLAB 源码、必要的绘图数据、矢量版 PDF/SVG 与论文使用的位图预览/插图。 |
| Codex 操作 PowerPoint | 可编辑的总体技术路线、系统结构、流程、决策树、实验/业务场景及由多个图件组成的说明版面。 | 不用手工拖拽重画统计结果或改动代码图的数值；流程关系需与正文一致；字体和线条需在最终 PDF 版面尺寸可读。定量图若放入版面，保留代码生成的原图。 | PPTX 可编辑源文件和最终导出件；记录图中符号、箭头和颜色的含义。 |

**快速选择：** 数值与统计证据优先 Python/MATLAB；方法逻辑或系统全景优先 PPT；只有非量化概念视觉考虑 GPT Image。工具可以协作：例如代码产生数据图，PPT 排列解释性流程图。但任何拼版或格式转换都要重新检查文字、坐标、色标和清晰度。

## 5. 全文图形规范

1. **先写图的论点。** 每幅图在绘制前登记“对应问题、单句结论、所需证据、数据/代码来源、验证边界、预期图题”。无法写出要证明什么的图先不进入正文。
2. **一图一主旨，多面板各有分工。** (a)、(b) 等面板承担互补证据，例如数据结构、结果、误差；相同信息不以不同指标重复堆放。版面允许时以一个主结果面板带辅助验证面板，不把所有子图做成同等显眼。
3. **统一可比编码。** 相同类别沿用同一颜色/顺序；相同变量、单位和物理量共用坐标范围、色条和精度。连续色值用有序色标，类别用可区分色；避免彩虹色和单靠红/绿表达差异，并检查灰度打印与色觉可读性。
4. **标注完整。** 坐标轴写变量和单位，注明范围、样本量、时间/空间条件、训练或测试集、误差线/区间定义及关键缩写。地图写方向、比例尺和坐标信息；三维场写清坐标、视角和色标。符号在图注或正文中定义。
5. **按最终版面检查。** 以最终 PDF 中实际显示尺寸（包含单栏/跨栏宽度）核对文字、图例、线宽、标记和注释；检查缩小后仍可辨认、没有遮挡/裁切/重叠。字体字号不设脱离页面尺寸的统一数字，应以正式模板和竞赛要求为准。
6. **图题与正文共同解释。** 图题简洁说明对象和内容；图注补充样本范围、统计口径、来源、颜色/符号含义及必要局限。正文指出图中哪项证据支持当前判断，而非仅重复图题。
7. **保持可追溯。** 数据处理、筛选、排除样本、聚合、拟合和颜色编码有记录；关键结果可由脚本重绘。不得把生成式示意图、示例数据或未经校准的模拟结果作为实证数据。

## 6. 从问题到交付的工作流

1. **建立图表清单：** 按题目小问列出结论、证据、图型、来源数据、生成脚本/工具和拟放章节；优先确定全篇技术路线图、数据质量图、各问核心结果和独立验证图。
2. **确定数据与验证边界：** 先完成数据审查。预测/分类任务按时间、对象、设备或批次切分后再拟合预处理步骤；作图时标明训练/验证/测试范围，不跨集合泄漏。
3. **规划阅读顺序与面板：** 画出图稿草案，标明各面板唯一作用；核对题目变量、符号和模型步骤，删除重复或不能支持主张的面板。
4. **选工具并生成：** 定量图用所选代码后端；示意图用可编辑绘图方式；AI 图像仅作受控的概念表达。保留每个图源文件和关键依赖说明。
5. **检查计算和视觉：** 核对样本数、统计量、单位、数据来源、模型拆分和图注；多面板检查对齐，所有图检查文字碰撞、裁切、颜色语义和不确定性表达。
6. **嵌入 LaTeX 论文并编译后复核：** 检查实际页宽下的可读性、分页/浮动位置、图号与正文引用；在最终 PDF 中核对清晰度和缩放效果。
7. **归档和更新：** 最终图件放在 `26-Modeling/003-Picture/`，分析/绘图脚本放在 `26-Modeling/002-Code/`，通用模板和样式放在 `Reference/002-绘图/`。图号、文件名、脚本输出和正文交叉引用保持一致。

### 每幅图的交付前核对表

- [ ] 这幅图的单句结论和所需证据已写清楚。
- [ ] 数据来源、样本量、筛选/排除规则与代码输出一致。
- [ ] 坐标、单位、类别顺序、颜色语义、范围和图注完整。
- [ ] 预测/分类拆分、误差/区间定义和验证集标注明确。
- [ ] 仿真、示意、无标签推断等证据边界没有被夸大。
- [ ] 多面板的面板标签、对齐、图例和文字无冲突，比较尺度一致。
- [ ] 在最终 PDF 页面宽度下检查过清晰度与裁切。
- [ ] 图件、源程序/可编辑文件、必要数据和正文图号可以互相追溯。
