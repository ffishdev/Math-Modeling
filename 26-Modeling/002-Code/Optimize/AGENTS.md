## 1. 工作目标与范围

- 本文件适用于 `26-Modeling/002-Code/Optimize/` 及其子目录，补充工作区根目录的协作约定。下文项目路径均相对于工作区根目录；目录树和 `Qn/...` 路径相对于 Optimize。
- 用户已有实现 D 题四个问题的基本代码，后续按用户指定的题目逐问优化。现有代码是待核验的起点，不能据此预设模型正确、结果可信或题面要求已全部满足。
- 优化最终服务于论文：重点是**完整且有依据的解题逻辑链条、模型与方法选择的论证，以及美观且承载证据的图片**。代码随模型调整、验证和绘图需求修正，不把代码重构、性能微调或增加算法数量作为主要成果。
- 每问完成时，必须同步交付该问的论文 LaTeX 正文、最终插图、必要的模型及辅助绘图代码、可核验结果和复现说明；不能只给修改建议、Notebook 或图片而留下空白章节。
- 当前按逐问优化推进，不自行展开其他题目的优化或整篇论文改写。若本问变化影响后续问的输入，应记录接口变化与待更新项，不把尚未重算的下游结果当成有效结果。

3. 检查当前问已有代码、参数、结果和运行说明，确认真实入口、依赖和输出来源。历史目录状态不等于当前状态，实际检查后再复用。
4. 按任务查阅 `Reference/004-数据建模手册.docx` 的相关方法与适用条件；阈值和模型清单只作候选依据。
5. 绘图前阅读 `Reference/002-绘图/绘图策略.md`。需细化图面风格时，按阅读报告的页码索引查看相关原论文代表图页；不能把读过总结说成已逐页审查原论文。
6. 写作前检查现有 LaTeX 模板与主论文的章节、符号、字体和图表规则。参考论文仅用于学习组织与表达，不照搬文字、图件、模型组合或数值。

## 4. 章节边界与论文逻辑

| 论文部分 | 当前处理范围 |
|---|---|
| 第 1–4 章：概述、问题分析、模型假设与符号等 | 暂不撰写或改写 |
| 第 5 章：数据预处理 | 暂不撰写或改写；本问需要的数据核验仍须完成 |
| 第 6 章 | 问题一，对应 `Q1/Q1-latex/Q1.tex` |
| 第 7 章 | 问题二，对应 `Q2/Q2-latex/Q2.tex` |
| 第 8 章 | 问题三，对应 `Q3/Q3-latex/Q3.tex` |
| 第 9 章 | 问题四，对应 `Q4/Q4-latex/Q4.tex` |
| 摘要、全篇总结及其他章节 | 暂不撰写或改写 |

每问围绕以下逻辑展开，按实际内容合并小节，不机械堆标题：

1. **任务与难点：** 准确说明本问目标、输入、输出、约束和与前问的关系，把实际难点转成需要解决的数学问题。
2. **思路与选型：** 从数据条件和问题结构说明合理基线、原方法不足、候选方法的适用性及最终取舍；解释每个新增模块解决什么问题。
3. **模型建立：** 定义本问新增变量、局部假设、参数来源、目标函数和约束，说明公式的现实含义及量纲。
4. **求解过程：** 交代输入如何进入模型、算法关键步骤、参数设置、停止条件和方案选取原则，让公式、程序和输出形成对应关系。
5. **结果与解释：** 直接回答题面要求，给出方案、指标和必要表格，用图表解释空间结构、资源配置、权衡或其他实际含义。
6. **验证与讨论：** 检查约束与计算正确性，给出适合本问的基线比较、敏感性、消融、稳健性或边界情形，说明结论和适用限制。

- 不重复撰写全局假设或整章预处理；本问必要的新增假设、特定数据变换和参数定义可以在本章交代。共享数据问题与待补的第 5 章内容记录在 Code 的说明中。
- 正文写成面向评阅者的连贯论证，避免操作日志、代码讲解、算法名列表和未落地的计划。不能用更多公式、更复杂模型或更多页数代替解释。
- 四问保持共享符号、单位和术语一致；引用前问结果时记录来源与版本，避免循环依赖或使用失效输出。

## 5. 模型与结果优化流程

1. **建立任务对应表。** 在本问 Code 的说明中逐项对应“题目要求—输入字段—现有方法—问题或缺口—拟用方法—验证证据—图表—正文位置”。
2. **复核已有基线。** 用正式输入检查现有实现与结果，重点核对业务含义、单位、目标和约束；可复用经核验部分，无需为了优化而全部重写。
3. **形成选型理由。** 综合可解释性、数据支持、求解规模、结果质量与实现代价选择方法。可精确求解时考虑线性/整数规划等基线；复杂算法仅在确有需要且可验证时引入。
4. **实现必要变化。** 同步修改受影响的模型、参数、验证和绘图代码；固定适用的随机种子，保存机器可读结果，确保正文关键数字可以追溯。
5. **验证后选定结果。** 在相同输入、约束、指标和可比计算条件下比较方案；报告改进幅度的基准、分母及代价，不只展示有利指标。未改善的尝试如实记录，允许保留更合适的基线。
6. **先结果与图，再完成正文。** 将经核验的证据组织成章节，并在 LaTeX 编译后检查文字与图表是否共同回答了本问。

验证必须匹配题型：优化结果检查所有硬约束及违反量，必要时用独立检查程序或小规模可精确求解实例交叉核验；启发式方法报告多次运行、运行预算、解的稳定性和终止状态。收敛曲线不能证明全局最优，只有适用的证明或求解器证据才支持最优性声明。多目标结果解释目标方向、归一化、权重和最终方案选择依据。

参数敏感性范围须有题面、资料或合理情景依据。情景仿真明确标注，不能冒充实测；由同一指标派生的相关量不能用来自证模型。若涉及预测或分类，遵守按时间或对象拆分、防泄漏与独立验证要求；无标签结果不能报告未经验证的准确率。

## 6. 图表设计与审美要求

- 绘图前列出“单句结论—所需证据—图表类型—数据/代码来源—本章位置—图注要点”。图表数量由论证需要决定，不为每问强配一套图或以图凑页。
- 借鉴阅读报告中的视觉逻辑：从场景/空间结构到模型处理，再到方案与验证。空间问题可用平面布局、关键剖面和方案指标互补；三维图需要时配二维投影，避免遮挡掩盖约束或差异。
- 方法流程图展示输入、变换、模型和输出的真实关系，不只排列算法名称。结果图说明得到什么，验证图说明结果为何可信，二者不能互相替代。
- 美观优先体现为清楚的视觉层级、克制且统一的配色、整齐对齐、合理留白与清晰文字。多面板各有作用，以 `(a)`、`(b)` 等标注，避免密集小图和重复信息。
- 四问统一字体、字号层级、线宽、颜色语义和数值精度。同一变量的对比图统一尺度与色标；连续量使用有序色标，类别使用可区分颜色，兼顾灰度与色觉可读性。
- 坐标、单位、图例、样本或情景范围齐全；地图保留坐标和空间比例，按需要标方向与比例尺；三维图说明高度与坐标轴含义。标注误差条或区间的计算定义。
- 定量图必须来自真实输入和可追溯计算；禁止为美观修改数值、平滑掉不利结果或生成虚假曲线。生成式图像只可承担明确标注的概念示意，关系也须核验。
- 定量绘图主要使用 Python/MATLAB；制作论文级 Python/R 图时按需使用 `nature-figure`，使用前读取当时的技能要求。绘图技能不替代建模与验证。
- 优先保存适合 LaTeX 的矢量 PDF；复杂栅格图采用在最终版面下足够清晰的 PNG 等格式。保留可编辑源文件或生图代码，不以截图作为最终定量图。
- 图题置下，表题置上；图注解释颜色、符号、范围和必要限制。正文必须引用并解释重要图表，避免只写“如图所示”。
- 所有最终插图放入本问 `figures/`，在编译后的 PDF 中按实际页面尺寸检查中文字体、文字碰撞、裁切、线条、图例和浮动位置；仅在绘图窗口放大查看不算完成质检。

## 7. LaTeX 与复现交付

- 将当前问内容写入对应 `Qn.tex`，形成可编译、可并入主论文的章节。开始前核对 `gmcmthesis.cls` 的实际章节层级，不假定存在 `\chapter`。
- 可采用独立预览入口加正文子文件；若将 `Qn.tex` 作为独立文档，则需清楚标出正文边界和合并方式。独立预览只调整相应章节计数器以对应第 6–9 章，不补写前五章或复制示例正文。
- 用 `\label`、`\ref`、`\eqref`、`\cite` 管理引用；标签按问题加前缀，避免合并冲突。章节、公式、图表编号由模板管理，不在标题中手工拼数字。
- 表格使用 `booktabs` 三线表；公式使用适当数学环境。参数、单位、符号与程序、结果表和图件一致，数值舍入遵循一致规则。
- 核验 XeLaTeX、latexmk 和中文字体；从本问 LaTeX 目录运行 `latexmk -xelatex -outdir=build Qn.tex`（替换为实际入口）。检查编译错误、缺图、缺失引用、溢出和最终 PDF 逐页版面；不能声称未执行的编译或视觉检查已通过。
- Code 的 README 记录实际核验的解释器、依赖、运行命令或 Notebook 执行顺序、随机设置和输出清单。优先核验并使用项目 `py310`，不修改全局 Conda 配置。
- 输入和输出采用相对路径或可配置项目根路径，不把个人机器绝对路径写死进分析程序。模型更新后同步重算依赖结果、重绘图件、更新正文数字并重新编译。
